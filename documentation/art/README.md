# Art pipeline and asset specs

All the game's art is currently **generated by Python scripts** in `tools/`.
They're placeholders that already follow the final formats, so any asset can
be redrawn by hand (in Aseprite) and dropped in without code changes, as
long as it keeps the layout described here.

> **Before replacing an asset by hand:** the scripts overwrite their PNGs
> every time they run. Once an asset is hand-drawn, stop running its script
> (or delete the script) so it can't clobber your work.

| Asset | File | Made by |
|---|---|---|
| Block / building tiles | `assets/tileset.png` | `tools/make_tileset.py` |
| Props (trees, rocks, tall grass) | `assets/props.png` | `tools/make_props.py` |
| Water surface and waterfall | `assets/water.png` | `tools/make_props.py` |
| Crops, tool icons | `assets/crops.png` | `tools/make_crops.py` |
| Player paper-doll layers | `assets/character/*.png` | `tools/make_character.py` |
| Buildings (geometry) | — | `scripts/buildings.gd` |

General rules for everything:

- **16 px = 1 world unit (one grid cell).** Keep that density everywhere so
  pixels match across tiles, props and characters.
- **Pixel-perfect PNGs.** No anti-aliasing, no semi-transparent pixels
  (alpha is either 0 or 255), and never JPEG.
- **Light comes from the top-left / above**, as in the DS Pokémon games.
- **Style target:** Pokémon Black & White / HGSS overworlds — original art in
  that style, never traced or edited from Nintendo sprites. See
  `documentation/concept/` for the look of the world.
- The camera is fixed, facing north and pitched 59° down (HGSS's camera).
  The world is stretched so **every texel looks the same size on screen**:
  blocks are tan(59°) ≈ 1.67 units tall, so a one-block cliff face shows
  as exactly one tile, and sprites (player, props, crops) stand upright,
  stretched by the same factor. So **draw everything straight on at 16 px
  per tile**; the player ends up just under two tiles tall.

## Aseprite setup

- Work in **Indexed** or **RGB** mode with a fixed palette per asset family
  (the palettes in the scripts are a good starting point).
- Use a grid matching the cell size (16×16 tiles, 32×32 characters, 32×48
  props) and enable *Snap to grid*.
- Keep one `.aseprite` source per asset family in a source folder (e.g.
  `art-src/`, outside `assets/` so Godot doesn't import it) and export PNGs
  into `assets/`.
- Export from the command line so exports are repeatable, for example:

  ```sh
  # One sheet per layer, for the character paper doll:
  aseprite -b art-src/character.aseprite --split-layers \
      --sheet-type rows --sheet "assets/character/{layer}.png"
  ```

  Check the result against the layouts below; Aseprite's sheet options
  (`--sheet-columns`, tags, borders and padding) must leave no padding
  between frames.
- After exporting, open the project in Godot once so it re-imports the PNGs,
  and commit both the PNG and its `.import` file.

## Player paper doll (`assets/character/`)

The player sprite is stacked from layers, recoloured, and outlined in game
(`scripts/appearance.gd`). Each layer is one PNG with **the same layout**:

- **32×32 frames, 7 columns × 5 rows** (224×160 px).
- **Rows (facings):** south, south-east, east, north-east, north. West,
  south-west and north-west are mirrored from these in game.
- **Columns (walk cycle):** `0` default/standing, then for the first leg
  `1` up, `2` contact, `3` passing, then the same for the other leg `4–6`.
  Each grid step plays half the cycle (default, up, contact, passing).
- **Feet** rest 2 px above the frame's bottom edge (soles on rows 28–29);
  the game puts that point on the ground. Characters are about 28 px tall,
  centred horizontally around x = 16.
- **No outlines.** The game outlines the stacked sprite, using a dark shade
  of whatever colour each outline pixel borders (DS style). Drawing your own
  outline would double it.

### Recolourable pixels

Each layer is drawn in a 4-shade ramp of **marker colours**, which the game
swaps for the player's chosen colour:

| Shade | Marker RGB |
|---|---|
| 0 (darkest) | `(40, 0, 255)` |
| 1 | `(100, 0, 255)` |
| 2 (base) | `(160, 0, 255)` |
| 3 (highlight) | `(220, 0, 255)` |

Any other colour is kept as drawn, for details that shouldn't recolour (a
cap's white badge, a jacket's white shirt, eye whites). Put the four markers
at the start of the Aseprite palette.

### Layers and draw order

Back to front: `body` (skin), `eyes`, `shoes`, `bottom_*`, `top_*`,
`hair_*`, `hat_*`. To add a style (say `hair_braid.png`), export it with the
same layout and add `"hair_braid"` to that slot's `styles` in
`Appearance.SLOTS`; it then shows up in the wardrobe.

Proportions the current layers use, which hand-drawn layers should keep
so they line up: head rows 4–13, eyes on row 9, neck row 14, torso rows
15–21, hands on row 21, legs from row 22, feet rows 28–29.

### Animation rules

From Bandygrass's 8-directional walk cycle tutorial and Chesu's PokeCommunity
overworld tutorial:

- **Up:** body lifts 1 px; the moving foot passes at its highest.
- **Contact:** feet and arms farthest apart. In front and back views the
  nearer foot is lower and wider, the farther foot higher and narrower.
- **Passing:** the back foot lifts.
- Arms swing opposite the legs.
- **Diagonals:** the leading side's arm and leg sit 1 px higher; the body
  turns (narrower torso, near side darker, far arm mostly hidden).
- Shade with 3 tones plus a highlight, lit from above and slightly toward
  the viewer. Hair is usually shiny.

## Tileset (`assets/tileset.png`)

- **16×16 tiles in a 4-column atlas**, read left to right, top to bottom, in
  the order of `GridWorld.Tex` (`scripts/world.gd`). Currently 4×5 tiles
  (64×80 px).
- Every tile must **tile seamlessly**: big faces (buildings) repeat tiles
  across themselves.
- Wall tiles hang from the top edge of the face they're on, so put features
  that belong at the top of a wall (the grass lip on `GRASS_SIDE`, the
  timber beam on `PLASTER`) at the top of the tile.
- Faces get fixed brightness by direction in game (tops brightest, faces
  turned away darkest), so draw tiles at full brightness and don't bake in
  that directional shading.
- **Adding a tile:** append its drawing to the atlas, add its name at the end
  of `GridWorld.Tex`, and raise `TEX_ROWS` if the atlas grows a row.

### Ledges and cliffs

Raised edges are dressed by `scripts/edges.gd` from three tiles:

- `LIP`: the rounded grass lip over every edge, wrapped over its curve
  from the top edge (row 0) to its underside (row 15). Keep the bright
  shoulder near the top and the dark outline at the bottom.
- `LEDGE_SIDE`: the one-tile earth face of ledges on gentle ground. Its
  top rows sit in the lip's shadow.
- `DIRT`: the rocky face of cliffs.

The ground at the foot of each face gets a soft shadow in game, so don't
draw one into the face tiles.

## Props (`assets/props.png`)

- **32×48 cells in a single row**, in the order of `GridWorld.PROP_SPRITES`:
  pine, snowy pine, boulder, bush, tall grass.
- The prop **stands on the cell's bottom edge, centred** (x = 16); the game
  places that point at the centre of its grid cell.
- Tall grass covers the lower part of whoever stands in it, so keep it
  short (about 8 px).

## Water (`assets/water.png`)

32×16: a 16×16 water surface tile on the left, a 16×16 waterfall tile on the
right. Both must tile seamlessly; the shader scrolls them (surfaces drift
south, waterfalls fall).

## Crops and tool icons (`assets/crops.png`)

- **16×16 cells, 8 columns.** One row per crop (`row` in `Crops.ALL`,
  `scripts/crops.gd`).
- Columns: `0` seeds in soil, `1–4` growth stages, `5` ready to harvest,
  `6` harvested item icon, `7` seed packet icon.
- The last row holds the tool icons (hoe, watering can) and the dead crop.
- Crops stand on the bottom edge of the cell, like props.

## Buildings (`scripts/buildings.gd`)

Buildings are low-poly meshes assembled in code from faces textured with the
tileset. A builder returns the footprint size, the door's column on the
front row, and the faces. To replace one with a hand-modelled mesh (e.g. from
Blender, exported as glTF):

- Keep the **footprint** (whole cells) and the **door column** the same, or
  update the builder's `size` and `door`.
- The model's origin is the footprint's north-west corner at ground level,
  +x east, +z south; the front faces south.
- Texture it from the tileset, or give it its own pixel-art atlas at the
  same 16 px per unit.
